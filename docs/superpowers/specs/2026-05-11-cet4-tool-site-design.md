# 四级真题工具站设计说明

## 目标

构建一个轻量的四级真题工具站，去掉常见的中间分发链路，让用户可以直接完成两件事：

1. 播放某套真题对应的听力音频
2. 下载该套真题的 PDF 文件

这个 MVP 的范围要故意收窄。它不是内容平台，不是社区，也不是完整的备考产品。它本质上是一个干净、直接的资料获取工具。

## 产品定位

这个站点存在的意义，是去掉下面这条常见链路：

`短视频 -> 公众号 -> 回复关键词 -> 网盘 -> 广告层 -> 转存 -> PDF`

我们想提供的体验是：

`打开 -> 找到真题 -> 播放听力或下载 PDF -> 离开`

这是一个典型的流量型工具站，但产品体验应该比常见的资料聚合页更干净。用户应该明显感觉到：这个网站是在直接把文件给他，而不是在中间层层截留流量。

## MVP 范围

### 包含

- 只做一个演示年份
- 按 `年份 -> 半年 -> 第几套` 的方式组织真题
- 首页作为站点入口页
- 单独的真题下载页
- 卡片内直接下载 PDF
- 单套试卷在线预览页
- 静态部署

### 不包含

- 答案版
- 解析版
- 批量下载
- 搜索
- 登录
- 用户账号
- 评论
- 后台 CMS
- 高频词汇功能实现

## 站点结构

这个站从一开始就应该采用多页面结构，而不是把首页当成整个产品本体。

### 页面划分

#### `/`

首页。它是站点入口页，不是完整真题档案页。

职责：

- 说明这个站是什么
- 清晰表达核心价值
- 把用户导向主要功能页
- 展示一小段轻量的真题预览
- 展示站点承诺或使用说明

首页默认不应该把完整真题档案全部展开。

#### `/papers`

真题下载页。这是 MVP 阶段最核心的工具页。

职责：

- 渲染当前可用年份的完整真题列表
- 按 `年份 - 上/下半年` 分组展示
- 每个半年默认展示 3 套试卷卡片
- 让用户点击卡片主体进入试卷预览页
- 让用户点击卡片内按钮直接下载对应 PDF

这个页面应该保持安静、直接、以完成任务为优先，而不是继续讲述站点理念。

#### `/papers/[year]/[month]/[setNumber]`

单套试卷预览页。

职责：

- 在线预览完整试卷内容
- 在预览页中继续提供 PDF 下载入口
- 为后续补充听力音频留出位置

MVP 阶段先做最简单的在线预览版，先跑通 `列表页 -> 预览页 -> 下载 PDF` 这条主链路，不强求一开始就做完整 PDF 查看器体验。

#### `/vocabulary`

为后续“高频词汇”功能预留的页面。

MVP 阶段的行为：

- 默认不在正式线上导航中显示这个页面
- 但代码结构和路由应提前为它预留位置

MVP 之后的方向：

- 近几年高频词汇
- 词义 / 例句 / 真题出处映射
- 按年份或频次筛选

这部分内容必须与真题下载流程保持分离，不要混进真题页里。

## 信息架构

### 全局导航

建议的顶级导航：

- 首页
- 真题下载
- 高频词汇
- 关于本站

在线上的 MVP 版本里，`高频词汇` 默认先隐藏，等页面有真实内容后再加入导航。但站点结构在设计时就要默认它未来会存在。

### 首页布局

建议首页包含这些区块：

1. Hero 区 / 价值陈述
2. 核心入口卡片或导航快捷入口
3. 轻量真题预览
4. 站点承诺 / 维护说明

首页应该更像一个结构清晰的总入口，而不是一张很长的单页档案页。

### 真题下载页布局

建议真题下载页包含这些区块：

1. 简洁页头
2. 年份分组区块
3. 各半年下的三张试卷卡片
4. 页脚中的 MVP 边界说明和后续功能提示

每个年份区块都应该做到无需额外点击就能快速扫描和操作。

## 内容模型

这个站本质上是内容驱动型网站，因此应使用简单的静态数据模型。

### 静态资源

- PDF 文件放在 `public/papers/...`
- 音频文件放在 `public/audio/...`

### 数据文件

使用一份结构化数据源，例如 `src/data/cet4.ts`。

每条真题记录建议包含：

- `id`
- `year`
- `month`
- `setNumber`
- `title`
- `pdfPath`
- `previewImagePath`
- `audioPath`
- `audioDuration`
- 可选的 `coverImage` 或预览相关元数据

示例结构：

```ts
type Cet4Paper = {
  id: string;
  year: number;
  month: 6 | 12;
  setNumber: number;
  title: string;
  pdfPath: string;
  previewImagePath?: string;
  audioPath?: string;
  audioDuration?: string;
};
```

这样后续每年维护时，流程就会非常简单：

1. 增加 PDF 和音频文件
2. 在数据文件中补一条记录
3. 重新部署

## 技术方向

推荐技术栈：

- Astro
- 静态资源托管
- 基于本地数据文件的数据驱动渲染

原因：

- 非常适合内容优先的静态工具站
- 对 SEO 友好
- 默认速度快
- 适合每年 6 月和 12 月固定新增真题的维护模式
- 后续要加新页面时，也不会把整个站拖成一个过重的前端应用

## 交互设计

### 真题卡片

每张真题卡片默认应承担两个独立入口：

- `点击卡片主体`：进入试卷预览页
- `点击下载按钮`：直接下载 PDF

这两个动作必须彼此独立，点击其中一个时，不能顺带触发另一个。

### 试卷预览页

- 当前阶段先做最简单在线预览版
- 支持在线查看完整试卷内容
- 提供明确的 PDF 下载入口
- 后续再升级为更完整的 PDF 查看器体验

### 音频

- 听力音频在当前 MVP 阶段可以暂缓实现
- 页面结构仍然要为后续补充音频留出扩展位

### PDF

- 下载必须是直接的
- 不允许跳转链路
- 不经过网盘中转
- 不加登录墙

## 视觉方向

当前确认的视觉方向，更接近“被认真整理过的档案馆 / 编辑部资料库”，而不是深色营销落地页。

设计原则：

- 浅色背景
- 有纸质感、档案感的视觉线索
- 强调“试卷本体”本身
- 为未来多页面扩展保留清晰导航结构
- 要有产品级精致感，但不要做成 startup landing page 的气质

视觉层级的重点是让用户觉得“真题本身才是主角”，而不是被装饰性框架抢走注意力。

## MVP 之后的扩展路径

当前结构已经天然指向后续三类主要功能：

1. 增加更多年份真题
2. 批量下载
3. 高频词汇页面

MVP 当前的结构不应该阻碍这三件事。

### 更多年份

这本质上只是数据扩充问题。页面结构和渲染模式不应该因此重写。

### 批量下载

这个能力后续应加在真题下载页，而不是首页。

### 高频词汇

这部分内容后续应作为独立页面实现，而不是嵌入真题档案页。

## 错误处理

MVP 阶段的错误处理可以保持简单：

- 如果某个 PDF 文件缺失，则隐藏下载按钮或展示不可用状态
- 如果某个音频文件缺失，则隐藏播放器状态或展示不可用状态
- 不要故意渲染出损坏链接

对于这个项目来说，更推荐使用构建时校验，而不是在运行时堆复杂逻辑。

## 测试

MVP 阶段最有价值的最小检查包括：

1. 数据文件可被正常解析
2. 每个引用的 PDF 路径都真实存在
3. 每个引用的音频路径都真实存在
4. 首页能正确渲染核心导航
5. 真题下载页能正确按年份渲染卡片分组
6. 下载链接都指向预期文件

这里的重点不是测试面铺得多广，而是避免上线后出现内容引用失效。

## 实现说明

建议的项目结构：

```text
src/
  pages/
    index.astro
    papers.astro
    vocabulary.astro
  components/
    layout/
    papers/
  data/
    cet4.ts
public/
  papers/
  audio/
```

这里最关键的一条架构规则是：

内容数据必须和页面结构分离，这样后续每年更新时，不需要反复改页面模板。

## 决策总结

当前已经确认的决策：

- 采用多页面站点结构
- 使用 Astro
- 首页是入口页，不是完整档案页
- 真题下载页是核心操作页
- 单套试卷预览页是列表页后的下一级页面
- 高频词汇是未来的独立页面
- 当前 MVP 先以 PDF 下载与在线预览为主
- 第一版只做一个演示年份
- 真题组织方式为 `年份 -> 半年 -> 第几套`

## 实现阶段待确定项

这些项不影响当前设计成立，但在实现时仍需要落具体值：

- 最终域名 / 部署目标
- 最终字体与品牌命名
- `高频词汇` 页面在实现前是否保留占位路由
- 真题资源文件的最终命名规范
